# Logging Ethereum Applications Based on Transaction Traces

This project logs execution data of decentralized applications (DApps) deployed to Ethereum.
The execution data is generated by recomputing transaction traces, i.e., the computational steps to process an Ethereum transaction.
For a user-defined block range, the program runs three stages:

1. **Extraction**: Recursively recreates transaction traces for contract addresses and discovers addresses belonging to a DApp by following CREATE-relations from contract deployments in the transaction trace data.
2. **Decoding**: Decodes the blockchain log entries and the input data of CALLs and DELEGATECALLs in the transaction traces based on contract ABIs.
3. **Transformation**: Transforms the decoded trace data into an event log for object-centric process mining (OCEL 2.0). The code in [log_construction](src/trace_based_logging/log_construction) is an example for the DApp Augur.


## Prerequisites

- Python 3.11 or later.
- An Etherscan API key. The transaction retrieval is in part based on querying normal transactions and internal transactions from Etherscan. Contract ABIs are fetched from Etherscan as well.
- An Ethereum archive node with a Geth-based client (e.g., Geth or Erigon).
  - Transaction retrieval by events (Ethereum log entries) uses the web3.py function [`eth.get_logs`](https://web3py.readthedocs.io/en/stable/web3.eth.html#web3.eth.Eth.get_logs).
  - Transaction traces are recreated with the Geth debug function [`debug_traceTransaction`](https://geth.ethereum.org/docs/interacting-with-geth/rpc/ns-debug#debugtracetransaction).


## Installation

1. Clone the repository:
```console
git clone https://github.com/rhobeck/trace_based_logging/
```

2. Install the required dependencies:
```console
pip install -r requirements.txt
```
`requirements.txt` pins the direct dependencies; `requirements.lock.txt` holds the complete environment of the run that produced the corrected dataset.


## Configuration

Before running the program, configure the JSON files in the project folder.

[config.json](config.json), a file with basic parameters:

- Ethereum Node Configuration (`ethereum_node`):
  - **`protocol`**: Protocol used for connection (`http://` by default).
  - **`host`**: IP address of the Ethereum archive node (`127.0.0.1` by default).
  - **`port`**: Port to connect to the Ethereum archive node (`8081` by default).

- Contracts (`contracts`):
  - **`dapp`**: List containing contract addresses that belong to the DApp.
  - **`non_dapp`**: List containing contract addresses explicitly excluded from the DApp.

- Block Range (`block_range`):
  - **`min_block`**: Minimum Ethereum block number for data extraction.
  - **`max_block`**: Maximum Ethereum block number for data extraction.

- Data Extraction (`extraction`):
  - **`normal_transactions`**: `true` to extract normal transactions from Etherscan.
  - **`internal_transactions`**: `true` to extract internal transactions from Etherscan.
  - **`transactions_by_events`**: `true` to extract transactions based on emitted blockchain events from the Ethereum node.
  - **`etherscan_api_key`**: API key for Etherscan, required to fetch data from Etherscan (ABIs, normal transactions, internal transactions). Replace the placeholder `ETHERSCAN_API_KEY`.

- Output Settings (`output`):

  - DApp-related (`dapp`):
    - **`events`**: Include events emitted by DApp contracts (`true`/`false`).
    - **`calls`**: Include calls involving Ether transfers to DApp contracts (`true`/`false`).
    - **`delegatecalls`**: Include delegatecalls to DApp contracts (`true`/`false`).
    - **`zero_value_calls`**: Include calls without Ether transfers to DApp contracts (`true`/`false`).
    - **`creations`**: Include creations of DApp contracts (`true`/`false`).

  - Non-DApp-related (`non_dapp`):
    - **`events`**: Include events emitted by non-DApp contracts (`true`/`false`).
    - **`calls`**: Include calls involving Ether transfers to non-DApp contracts (`true`/`false`).
    - **`delegatecalls`**: Include delegatecalls to non-DApp contracts (`true`/`false`).
    - **`zero_value_calls`**: Include calls without Ether transfers to non-DApp contracts (`true`/`false`).
    - **`creations`**: Include creations of non-DApp contracts (`true`/`false`).

- Processing Stages (`stages`):
  - **`extraction`**: Enable or disable the extraction stage (`true`/`false`).
  - **`decoding`**: Enable or disable the decoding stage (`true`/`false`).
  - **`transformation`**: Enable or disable the transformation stage (`true`/`false`).

- Miscellaneous (`misc`):
  - **`sensitive_events`**: Enable or disable creating events with context information (e.g., by role of the involved contract; `true`/`false`).
  - **`log_folder`**: Name of the output folder in [resources](resources) (`output` by default).
  - **`ordering`** (optional): Order of the operations within a transaction trace. `paper` (default) is the enumeration used for the published data; `exact` is for validation and requires a client that reports the position of log entries in the trace (Geth 1.13.5 or later).

[config_custom_events.json](src/trace_based_logging/trace_decoder/config_custom_events.json), a file with ABI specifications for decoding the data. If the ABI of a contract is not available (on Etherscan), a contract's events or functions can be decoded with fall-back specifications. By default this includes ABI specifications to decode the events from the standards ERC-20, ERC-721, ERC-777, and ERC-1155 (and two custom Augur events).

[mappings.json](src/trace_based_logging/log_construction/mappings.json), a file with mappings for data transformation (e.g., semantics and context information).


## Usage

To execute the main function of the project, run from the project folder:
```console
python src/trace_based_logging/__main__.py
```

Alternatively, run the program without installing the dependencies through uv:
```console
uv run --no-project --with-requirements requirements.txt python src/trace_based_logging/__main__.py
```

Every stage is checkpointed, so that an interrupted run resumes where it stopped when it is started again.

### Output

The output files are saved to [resources](resources), and therein to the output folder specified in the `config.json`. The output is structured by the stage it was created in:

- **`extraction`**
  - Tabular transaction trace data
  - List of contracts identified as belonging to the DApp
  - Transaction receipts (transaction index, revert status) in the shared cache
  - Checkpoints and part files that let an interrupted run resume

- **`decoding`**
  - Tabular data of creations identified in the trace data
  - Dictionary of ABIs available for the identified contracts
  - Tabular data of events, calls, zero-value calls, and delegate calls. Divided in DApp and non-DApp. Decoded where possible.

- **`transformation`**
  - Tabular contextualized and formatted data of events, calls, zero-value calls, and delegate calls. Divided in DApp and non-DApp.
  - Account types (EOA or contract) per address
  - Relational OCEL 2.0 tables (events, objects, event-to-object relations, object-to-object relations, object attribute changes) as parquet files in `log_paper/`
  - OCEL 2.0 event log as SQLite. An XML export is implemented, but switched off in the main function.

Two caches are shared across runs in `resources/cache`: the transaction receipts fetched from the node (`receipts.parquet`) and the contract ABIs fetched from Etherscan (`abi_cache.parquet`). A run fetches only what the caches lack. The folder can be deleted; the next run fetches again.

python -m pytest tests

## Correction of the event log (2026)

The event log published with the paper contains 2,016,339 of the intended 11,074,940
events. The log construction defined the event IDs based on a row index that was not
unique after the five tables of operations had been concatenated. Events of different
tables received the same ID, and only one event per ID entered the event log. Events
without a relationship to an object were left out as well.

This repository holds the corrected implementation: event IDs are defined based on the
transaction hash and the position in the transaction trace, and every event is related
to at least one object. The corrected event log contains 11,074,965 events; 25 of them
stem from two failed transactions that the original data extraction had missed.

- Corrected event log: [Zenodo, DOI 10.5281/zenodo.24388223](https://doi.org/10.5281/zenodo.24388223)
- Code that constructed the published event log: tag
  [`EMISAJ-2025`](https://github.com/rhobeck/trace_based_logging/tree/EMISAJ-2025)
- Data and code of the figures in the corrected paper: [figures](figures)

The figure analyses were implemented by
[Alessandro Berti](https://github.com/fit-alessandro-berti)
([figures/regenerate_figures.py](figures/regenerate_figures.py)).
